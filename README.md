### 1. Постановка задачи

**Задание 1.** Вычислить значение выражения при различных вещественных типах данных (`float` и `double`):

$$
\frac{(a-b)^4 - (a^4 - 4a^3 b)}{6a^2 b^2 - 4ab^3 + b^4}
$$

при \(a = 100\), \(b = 0.001\).

Вычисления выполнять с использованием промежуточных переменных. Сравнить и объяснить полученные результаты.

**Задание 2.** Вычислить значения выражений и объяснить полученные результаты:

1) `n++ * m`
2) `n++ < m`
3) `m-- > m`

### 5. Объяснение результатов задания 1

**Аналитическая проверка.** Раскроем \((a-b)^4\):

$$
(a-b)^4 = a^4 - 4a^3 b + 6a^2 b^2 - 4ab^3 + b^4
$$

Тогда числитель:

$$
(a-b)^4 - (a^4 - 4a^3 b) = 6a^2 b^2 - 4ab^3 + b^4
$$

То есть **числитель тождественно равен знаменателю**, и точный ответ — **1**.

**Почему `float` даёт неверный результат.** Числа \(a^4 = 10^8\) и \((a-b)^4 \approx 10^8\) имеют порядок \(10^8\). Мантисса `float` содержит ~24 бита, что даёт ≈ 7 значащих десятичных цифр. Для числа порядка \(10^8\) младший представимый разряд — это ≈ 10. Истинная разность числителя должна быть ≈ 0.06, но она **меньше шага сетки `float`**, поэтому округляется до 0 или до кратного 10. Вместо 0.06 получается «мусор» порядка \(10^4\). Это классическая **катастрофическая потеря точности** при вычитании двух близких больших чисел.

**Разница между `powf` и `pow` во float-решении.**
- `powf(a, b)` — «родная» функция для `float`: аргументы и результат остаются во `float`.
- `pow(a, b)` — функция для `double`: `float`-аргументы неявно расширяются до `double`, вычисление идёт в `double`, результат урезается обратно до `float`.

Разница проявляется **только на этапе возведения в степень**. Но главная потеря точности происходит **позже** — при вычитании `num1 - num2`, где оба числа имеют порядок \(10^8\). Поэтому **`pow` не спасает `float`-решение**: проблема не в функции, а в самом типе `float`.

**Почему `double` даёт правильный результат.** `double` имеет мантиссу ~53 бита (~16 значащих цифр). Младший представимый разряд для чисел порядка \(10^8\) — это ≈ \(10^{-7}\), чего достаточно, чтобы сохранить разность 0.06. Результат получается ≈ 1, что совпадает с аналитическим ответом.

**Разница между `float` и `double` в вычислениях:**

| Параметр | `float` | `double` |
|---|---|---|
| Размер | 32 бита | 64 бита |
| Мантисса | ~24 бита (~7 цифр) | ~53 бита (~16 цифр) |
| Диапазон | ≈ \(10^{\pm 38}\) | ≈ \(10^{\pm 308}\) |
| Точность | ниже | выше |

Чем больше мантисса, тем меньше относительная погрешность и тем позже наступает потеря точности при вычитании близких чисел или накоплении ошибок в длинных вычислениях.

**Зачем нужен `float`, если `double` точнее.** `double` точнее, но **не бесплатен**: он занимает вдвое больше памяти, а операции с ним на многих архитектурах (GPU, ARM, встраиваемые системы) выполняются медленнее и энергозатратнее. `float` выбирают, когда точности 7 знаков достаточно, а ресурсы ограничены.

**Где применяют `float`:**

1. **Графика и игры** — координаты, цвета, нормали, матрицы. Точности 7 знаков хватает для визуализации, а `double` вдвое увеличивает объём видеопамяти и снижает FPS.
2. **Машинное обучение** — веса и активации нейросетей. Данные и так зашумлены, а скорость и память критичны.
3. **Встраиваемые системы и микроконтроллеры** — мало RAM/ROM, часто нет аппаратного `double`. Там `float` — единственный практичный вариант.
4. **GPU-вычисления** — на видеокартах `float` в разы быстрее `double` (иногда в 16–32 раза).
5. **Большие массивы данных** — экономия памяти: 1 млн чисел в `float` = 4 МБ, в `double` = 8 МБ.
6. **Аудио/видео в реальном времени** — важна пропускная способность, а не 16-значная точность.
7. **Стандартизованные форматы** (STL, glTF, HDR) — зафиксированы на 32 битах.

**Случаи, где справится только `float`:**

- Формат данных жёстко задан (4 байта IEEE 754).
- Аппаратура физически не поддерживает `double` (некоторые MCU, старые GPU).
- Скорость критична настолько, что 2× замедление от `double` неприемлемо.
- Память — узкое место, массив должен помещаться в кэш/VRAM.

Во всех остальных случаях `double` — «безопасный выбор по умолчанию», а `float` — осознанный компромисс ради скорости, памяти или совместимости.

### 6. Программа решения задания 2

```cpp
#include <iostream>              // стандартный ввод/вывод
#include <clocale>               // локализация кириллицы

using namespace std;             // пространство имён std

int main()                       // точка входа
{
    setlocale(LC_ALL, "Russian"); // русская локализация
    int n, m, r;                  // целочисленные переменные

    // 1) n++ * m
    n = 5; m = 3;                 // начальные значения
    r = n++ * m;                  // n++ возвращает 5, 5*3=15, затем n=6
    cout << "1) n++ * m = " << r << ", n = " << n << ", m = " << m << "\n";

    // 2) n++ < m
    n = 5; m = 3;                 // сброс значений
    r = n++ < m;                  // n++ возвращает 5, 5<3 ложно -> 0, n=6
    cout << "2) n++ < m = " << r << ", n = " << n << ", m = " << m << "\n";

    // 3) m-- > m
    n = 5; m = 3;                 // сброс значений
    r = m-- > m;                  // m-- возвращает 3, m=2, затем 3>2 -> 1
    cout << "3) m-- > m = " << r << ", n = " << n << ", m = " << m << "\n";

    return 0;                     // успешное завершение
}
```

3) m-- > m = 1, n = 5, m = 2

### 8. Объяснение результатов задания 2

**1) `n++ * m`.** `n++` — **постфиксный** инкремент: возвращает **старое** значение `n` (5), и только потом увеличивает `n` до 6. Умножение: `5 * 3 = 15`. После операции: `n = 6`, `m = 3`. **Результат: 15.**

**2) `n++ < m`.** `n++` снова возвращает **старое** значение `n` (5), затем `n` становится 6. Сравнение: `5 < 3` → **ложь** → `0`. После операции: `n = 6`, `m = 3`. **Результат: 0 (false).**

**3) `m-- > m`.** `m--` — постфиксный декремент: возвращает **старое** значение `m` (3), затем `m` становится 2. Правый операнд `m` во втором вхождении — это уже **новое** значение `m` (2). Сравнение: `3 > 2` → **истина** → `1`. После операции: `n = 5`, `m = 2`. **Результат: 1 (true).**

> **Важное примечание.** До стандарта C++17 порядок вычисления операндов оператора `>` был **не определён**, поэтому выражение `m-- > m` могло давать разный результат в разных компиляторах (классический пример **undefined behavior**). Начиная с C++17 порядок вычисления зафиксирован: **слева направо**. Поэтому в современных компиляторах результат стабильно равен 1.

**Общий вывод по заданию 2.** Постфиксные `++` и `--` возвращают **старое** значение переменной и лишь затем изменяют её. Именно это определяет результат всех трёх выражений. Выражение `m-- > m` — наглядный пример взаимодействия побочного эффекта и чтения переменной в одном выражении: до C++17 это было UB, в C++17+ результат детерминирован.

### Общий вывод по работе

В задании 1 наглядно показано, что **точность вещественного типа критически влияет на результат** при вычитании близких больших чисел. `float` с мантиссой ~24 бита не способен удержать разность 0.06 между числами порядка \(10^8\), поэтому даёт «мусорный» результат. `double` с мантиссой ~53 бита справляется и даёт аналитически верный ответ ≈ 1. Замена `powf` на `pow` в float-решении **не меняет картину**, потому что главная потеря точности происходит не в возведении в степень, а в последующем вычитании — то есть проблема не в функции, а в самом типе данных.

В задании 2 продемонстрирована работа постфиксных инкремента/декремента: они возвращают **старое** значение переменной, а изменение происходит уже после использования. Это объясняет результаты 15, 0 и 1. Отдельно отмечен случай `m-- > m` — пример неопределённого поведения до C++17 и детерминированного результата в C++17+.
